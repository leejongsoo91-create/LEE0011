# 부서별 규칙 템플릿 (Micro Rulebook)

새 실무 부서를 만들 때 이 파일을 복사해 `<부서이름>.md`로 저장하고 `< >` 부분을 채운다.
전사 공통 규칙(`global_rules.md`)은 모든 부서에 자동 적용되며, 이 문서는 그 위에 부서만의 제한을 **더하기만** 한다. 공통 규칙을 완화할 수는 없다.

> 이 파일의 `< >`는 채워 넣을 자리다. 값이 비어 있으면 그 부서는 등록할 수 없다.

---

## 1. 부서 정보

| 항목 | 내용 |
| --- | --- |
| 부서 이름 | `<예: 파이프라인 팀 / 대시보드 관리 팀 / 리서치 팀>` |
| 식별자 | `<영문 소문자와 밑줄, 예: dashboard_admin>` |
| 한 줄 역할 | `<이 부서가 맡는 일>` |
| 맡지 않는 일 | `<다른 부서로 넘길 일>` |

## 2. 역할과 책임

- `<이 부서가 하는 일 1>`
- `<이 부서가 하는 일 2>`

## 3. 허용된 도구

도구는 레지스트리(`registry.js`)에 등록된 이름만 쓴다. 표에 없는 도구는 이 부서가 호출할 수 없다.

| 도구 이름 | 위험도 (`read` / `write` / `irreversible`) | 설명 | 되돌리는 방법 (`write`는 필수) |
| --- | --- | --- | --- |
| `<tool_name>` | `<read>` | `<무엇을 하는지>` | `<해당 없음>` |
| `<tool_name>` | `<write>` | `<무엇을 하는지>` | `<예: 등록한 id를 삭제>` |

## 4. 접근 제한 구역

| 구분 | 내용 |
| --- | --- |
| 접근 허용 | `<테이블, 폴더, 외부 서비스 목록>` |
| 접근 금지 | `<명시적으로 막을 대상>` |
| 읽기만 허용 | `<수정하면 안 되는 대상>` |

허용 목록에 없는 곳은 모두 금지로 본다.

## 5. 필수 파라미터

도구 호출 전에 아래 값이 모두 확인되어야 한다. 하나라도 비면 추측하지 않고 캡틴에게 되묻는다. (`global_rules.md` G-2)

| 도구 | 필수 파라미터 | 형식·제약 | 모호할 때 되물을 말 |
| --- | --- | --- | --- |
| `<tool_name>` | `<param>` | `<예: YYYY-MM-DD, 비어 있으면 안 됨>` | `<예: 어느 날짜인가요?>` |

## 6. 결재 요약에 반드시 넣을 내용

- 무엇을 (대상 항목, 바뀌는 값 전후)
- 몇 건을
- 되돌릴 수 있는지 / 되돌릴 수 없는지
- `<이 부서가 추가로 보여줄 항목>`

## 7. 부서별 추가 금지·주의 사항

- `<예: 한 번에 N건 이상 삭제 금지>`
- `<예: 외부 서비스 호출은 계획의 마지막 단계에만>`

## 8. 부서 추가 체크리스트

- [ ] 도구마다 위험도가 정해져 있다
- [ ] `write` 도구마다 되돌리는 방법이 정의되어 있다
- [ ] 접근 허용 구역이 최소한으로 좁혀져 있다
- [ ] 필수 파라미터와 되물을 말이 도구마다 적혀 있다
- [ ] 레지스트리에 부서와 도구를 등록했다
- [ ] 모의 지시로 계획 → 검증 → 결재 → 실행 → 원복 경로를 테스트했다

# 부서별 규칙 템플릿 (Micro Rulebook)

새 실무 부서를 만들 때:

1. `api/_agents/depts/<부서 id>/` 폴더를 만든다. (`depts/schedule/`을 본보기로)
2. 이 파일을 그 폴더에 `rules.md`로 복사하고 `< >` 부분을 채운다.
3. `tools.js`에 도구를 만든다. 도구 이름은 `<부서 id>.<이름>` (예: `work.list`).
4. `index.js`에 부서 등록 정보(id, 이름, 한 줄 역할, 지시 예시, 규칙서 위치, 도구 목록)를 적는다.
5. `depts/index.js`의 `DEPARTMENTS` 목록에 한 줄 추가한다. 규칙서 읽기·결재 메시지·검증은 자동으로 따라온다.
전사 공통 규칙(`global_rules.md`)은 모든 부서에 자동 적용되며, 이 문서는 그 위에 부서만의 제한을 **더하기만** 한다. 공통 규칙을 완화할 수는 없다. 단, G-2가 허용하는 해석 방법(기본값, 모호한 표현을 해석하는 기준)은 이 문서에서 정할 수 있다.

> 이 파일의 `< >`는 채워 넣을 자리다. 값이 비어 있으면 그 부서는 등록할 수 없다.

## 3. 허용된 도구

도구는 레지스트리(`registry.js`)에 등록된 이름만 쓴다. 표에 없는 도구는 이 부서가 호출할 수 없다.

| 도구 이름 | 위험도 (`read` / `write` / `irreversible`) | 설명 | 되돌리는 방법 (`write`는 필수) |
| --- | --- | --- | --- |
| `<tool_name>` | `<read>` | `<무엇을 하는지>` | `<해당 없음>` |
| `<tool_name>` | `<write>` | `<무엇을 하는지>` | `<예: 등록한 id를 삭제>` |

| 구분 | 내용 |

## 6. 결재 요약에 넣을 내용

- 무엇을 (대상 항목, 바뀌는 값 전후)
- 몇 건을
- 되돌릴 수 있는지 / 되돌릴 수 없는지
- `<이 부서가 추가로 보여줄 항목>`

## 7. 부서별 추가 금지·주의 사항

- `<예: 한 번에 N건 이상 삭제 금지>`
- `<예: 외부 서비스 호출은 계획의 마지막 단계에만>`

## 8. 부서 추가 체크리스트

- [ ] 도구마다 위험도가 정해져 있다
- [ ] `write` 도구마다 되돌리는 방법이 정의되어 있다
- [ ] 접근 허용 구역이 최소한으로 좁혀져 있다
- [ ] 필수 파라미터와 되물을 말이 도구마다 적혀 있다
- [ ] 부서 폴더(`index.js`, `tools.js`, `rules.md`)를 만들고 `depts/index.js`에 등록했다
- [ ] 모의 지시로 계획 → 검증 → 결재 → 실행 → 원복 경로를 테스트했다
